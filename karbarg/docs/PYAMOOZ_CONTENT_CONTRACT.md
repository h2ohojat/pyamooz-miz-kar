# قرارداد تولید و اتصال محتوای تعاملی پای‌آموز

Pyamooz Interactive Content Contract — Lessons, Worksheets & Games

نسخهٔ سند: **۱٫۲٫۰** — ۲۰۲۶-۱۰-۰۲؛ نویسندهٔ این اصلاح: **OpenAI Codex، مبتنی بر GPT-6**، به درخواست مالک.
مرجع فنی اتصال، همین فایل در مخزن سایت `h2ohojat/pyamooz_newversion` است؛ نسخهٔ هماهنگ‌شدهٔ آن همراه موتور در `D:\alavi\docs` قرار می‌گیرد. قواعد تولید و فرمان‌های سازنده در `AUTHORING_GUIDE.md` مخزن موتور هستند. نسخهٔ موتور، محتوا، سند، پل و ساختار state مستقل‌اند.

## ۱. دلیل الزام و وضعیت واقعی

مالک خواسته است افزودن هر محتوا بدون کد اختصاصی در Laravel ممکن باشد و پیشرفت و گزارش کاربران حفظ شود. شناسنامه، پل و نسخهٔ محتوا برای همین هدف الزامی‌اند؛ نام نویسنده به‌تنهایی اعتبار فنی نیست. این استاندارد داخلی پروژه است. دستور صریح تازهٔ مالک مقدم است و تصمیم تغییردهنده در قرارداد ثبت می‌شود.

میزبان بازی، SDK، پنل، ذخیره/ادامه و چهار بازی اولیه در پای‌آموز ساخته شده‌اند؛ گزارش‌های Issue83 تا95 و `docs/games-handoff-qa.fa.md` سابقهٔ آن‌اند. موتور محتوای محلی اکنون درس و کاربرگ را با موتور ۱٫۲٫۱ و بازی را با کپی قفل‌شدهٔ SDK واقعی می‌سازد. تغییر این سند مجوز انتشار محتوا یا سایت نیست.

| محتوا | قالب و پیام | محل افزودن |
| --- | --- | --- |
| درس | LESSON، kz-meta، kelas v1 | پنل درس |
| کاربرگ تعاملی | همان LESSON با layout برابر worksheet، همان پل و گزارش درس | پنل درس |
| بازی | manifest، pyamooz-game-meta، pyamooz-game v1 | پنل بازی |

کاربرگ درس‌محور است؛ رکورد بازی با نمره/ستارهٔ درس مخلوط نمی‌شود. یک ابزار ساخت و منابع مشترک داریم؛ قرارداد جدید برای هر محتوا یا موتور موازی ساخته نمی‌شود.

## ۲. بسته و اجرای ایمن

- یک HTML کامل UTF-8، فارسی و RTL، با viewport و همهٔ منابع داخلی؛ سقف ۵ MiB.
- CDN، منابع نسبی بیرونی، fetch/XHR، WebSocket و beacon در محتوا مجاز نیست. شبکه و هویت وظیفهٔ میزبان‌اند.
- اجرا در `iframe sandbox="allow-scripts"`، بدون allow-same-origin. CSP میزبان برای راه‌اندازی یک محتوا ضعیف نمی‌شود.
- eval، Function پویا و iframe داخلی مجاز نیستند. Worker از blob در CSP فعلی مجاز است؛ کدنویسی با مفسر آموزشی محدود انجام می‌شود.
- نبود localStorage، clipboard، fullscreen، popup یا صدا نباید فعالیت اصلی را خراب کند. در standalone ذخیره خطاپذیر است؛ ذخیرهٔ حساب فقط از پل می‌آید.
- state/result/summary حداکثر ۲۵۶ KiB JSON UTF-8؛ فقط دادهٔ سریال‌پذیر، بدون DOM، تابع، Promise یا ارجاع دوری.
- محتوا فقط از window.parent و میزبان فقط از iframe.contentWindow پیام می‌پذیرند؛ namespace، نسخه، session و شکل داده کنترل می‌شوند. origin به‌تنهایی کافی نیست؛ origin قاب می‌تواند null باشد.
- محتوا به DOM والد، کوکی، حساب، پایگاه داده و کلید سرویس دسترسی ندارد. هویت و مجوز از سمت سرور تعیین می‌شوند.
- منابع خصوصی و gitignored بدون دستور مالک به مخزن عمومی فرستاده نمی‌شوند. برند و حقوق محتوا حفظ می‌شوند؛ کلیک روی کانال شرط فنی ادامه نیست.

## ۳. شناسه، نسخه و ساخت

شناسهٔ محتوا: `^[a-z0-9][a-z0-9-]{0,63}$`؛ ثابت و مستقل از عنوان. version عدد صحیح مثبت JSON است و با تغییر بستهٔ تحویلی افزایش می‌یابد. version یکسان با فایل متفاوت، اصلاح نسخهٔ قبلی محسوب نمی‌شود.

هر فعالیت تعاملی id کوتاه انگلیسی، یکتا و ثابت دارد؛ شناسهٔ موقعیتی s3 مجاز نیست. id داخل منبع نوشته می‌شود؛ build آن را از ترتیب یا متن حدس نمی‌زند. تغییر ترتیب، نوع، معنای پاسخ یا state می‌تواند ذخیرهٔ قدیمی را ناسازگار کند؛ id ثابت به‌تنهایی مهاجرت نیست.

شناسنامه دقیقاً یک script از نوع application/json در head دارد و بدون اجرای کد خوانده می‌شود. منبع اصلی و شناسنامهٔ runtime/static یک کاتالوگ دارند. حذف شناسنامه برای پنهان‌کردن خطا ممنوع است. build خطای شناسه، مجوز، نسخه، JavaScript یا وابستگی ممنوع را پیش از نوشتن خروجی رد می‌کند.

## ۴. قرارداد درس و کاربرگ — kelas v1

بلوک `id="kz-meta"`: kz برابر عدد۱، engine نسخهٔ واقعی، id، version، title، contentMode، licenseNumber، objectives، duration و items. موارد items شامل id، idx از صفر، type، stage، gated، scored، q متن ساده و tags هستند. maxStars با قواعد واقعی موتور محاسبه می‌شود؛ نمایهٔ academic ستاره ندارد.

contentMode یکی از syllabus یا textbook-licensed است. حالت دوم شمارهٔ مجوز معتبر در فایل یا پنل لازم دارد؛ انتخاب یک برچسب جای کسب مجوز را نمی‌گیرد. سازندهٔ موتور بدون مجوز، فایل کتاب‌محور را آمادهٔ انتشار معرفی نمی‌کند.

پوستهٔ پیام: `{ns: 'kelas', v: 1, kind: ...}`.

| جهت و kind | وظیفه |
| --- | --- |
| محتوا → میزبان، hello | engine، session، caps، lesson و کاتالوگ واقعی |
| میزبان → محتوا، init | persist، learner اختیاری، state سازگار و mode |
| محتوا → میزبان، state | session، lesson و snapshot کامل |
| محتوا → میزبان، event | رویدادهای تعامل؛ lesson.complete هنگام رسیدن واقعی به پایان |
| محتوا → میزبان، summary | session، lesson و summary مستقل؛ فقط lesson.summary کافی نیست |
| میزبان → محتوا، command | goto، mode یا summary |

session حداکثر۴۰ نویسهٔ لاتین/عدد/_/- دارد. init تکراری فعالیت را از نو نمی‌سازد. در کاربرگ تمرین‌ها به ترتیب دلخواه در یک صفحه حل می‌شوند؛ ورود به صفحه پایان محسوب نمی‌شود. گزارش با تکمیل تمرین‌ها و انتخاب کاربر باز می‌شود. خودارزیابی و تأمل، summary را به‌روز می‌کنند؛ summary.final طبق تکمیل خودارزیابی تعیین می‌شود.

summary.pct درصد نمره است؛ درصد پیمودن نیست. tries در موتور تعداد خطاهاست. معنای فیلدهای گزارش برای قابلیت تازه عوض نمی‌شود.

custom از api.state و api.save استفاده می‌کند؛ api.right/wrong/done تکمیل را اعلام می‌کنند. ورودی ناقص، دادهٔ تصادفی، مرحلهٔ داخلی و زمان لازم برای ادامه در state هستند. کار async از api.isActive و api.onDispose استفاده می‌کند؛ پس از خروج، worker/timer/listener مربوط کنار گذاشته می‌شود.

میزبان هنگام POST state، revision سرور را ارسال می‌کند. ذخیره زیر قفل پروفایل/وضعیت ثبت و revision افزایش می‌یابد؛ تکرار عین بسته receipt قبلی می‌گیرد و ذخیرهٔ کهنه409 می‌شود. بازیابی تعارض ابتدا کپی محلی را حفظ می‌کند. این revision به پل محتوای درس افزوده نمی‌شود و مسئولیت میزبان است.

## ۵. قرارداد واقعی بازی — pyamooz-game v1

بلوک `id="pyamooz-game-meta"` دقیقاً یک script application/json و حداکثر۳۲ KiB است. schemaVersion و bridge.v عدد۱؛ kind برابر game؛ bridge.ns برابر pyamooz-game. stateSchemaVersion عدد صحیح۱ تا۶۵۵۳۵؛ version عدد صحیح۱ تا۲۱۴۷۴۸۳۶۴۷. title حداکثر۱۶۰ نویسه.

mode یکی از levels، puzzle یا endless؛ levels برای حالت levels لازم است و فقط مراحل واقعاً قابل بازی را شامل می‌شود. قابلیت‌های لازم دقیقاً state، resume، result و pause هستند.

metrics یک تا۱۶ معیار دارد: id یکتا، label، type برابر integer/number، min نامنفی و محدود، max اختیاری تا۱۰^۱۲، best برابر min/max/none؛ unit و recordOn اختیاری. recordOn از won/lost/completed می‌آید. زمان دور رهاشده رکورد حل نیست.

settings حداکثر۸ تنظیم است: id، label، options یک تا۲۰ مقدار رشته‌ای و default از همان options. نام‌های __proto__، constructor و prototype برای تنظیم/معیار ممنوع‌اند. ruleset شرایط مقایسه را مشخص می‌کند. تنظیم مؤثر بر قواعد در میانهٔ دور خاموش عوض نمی‌شود.

منبع SDK `pyamooz/resources/games/shared` در مخزن میزبان است. سازندهٔ مستقل، کپی هماهنگ با commit و SHA-256 آن را مصرف می‌کند؛ SDK دستی و قرارداد موازی نمی‌سازد.

| kind | دادهٔ مهم |
| --- | --- |
| hello | session، game: {id, version}، capabilities |
| init | session، runId، persist، stateSchemaVersion، state، stateRevision، settings، preferences؛ status/terminal برای دور نهایی |
| state | session، runId، seq، baseRevision، stateSchemaVersion، snapshot کامل state |
| result | همان فیلدهای state و snapshot نهایی؛ resultId، outcome، metrics، elapsedMs |
| checkpoint | snapshot جدیدِ هنوز معطل receipt؛ afterSeq، baseRevision، stateSchemaVersion، state و terminal اختیاری |
| ack | session، runId، for، seq، stateRevision؛ stored برابر server/local؛ resultId برای نتیجه |
| command | pause، resume، snapshot یا preferences |
| error | session، runId در صورت تخصیص، code و پیام امن |

seq افزایشی در session/run است. در هر لحظه یک receipt درحال ارسال است؛ تغییر جدید هنگام انتظار از بین نمی‌رود. ارسال دوباره همان seq همان packet را دارد. ack فقط پس از ثبت واقعی صادر می‌شود؛ revision آن baseRevision+1 است.

persist یکی از account/guest/none است. پیش‌نمایش none به‌معنی ثبت در حساب نیست. init تکراری بازی را reset نمی‌کند. runId متعلق به میزبان و نسخهٔ run ثابت است؛ هویت از packet بازی تعیین نمی‌شود.

outcome یکی از won، lost، completed یا abandoned؛ در هر دور فقط یک نتیجهٔ نهایی. resultId تکراری با بدنهٔ متفاوت رد می‌شود. pause/خروج موقت نتیجهٔ نهایی نیست. milestone بازی بی‌پایان مانند رسیدن به۲۰۴۸ الزاماً پایان نیست.

snapshot نهایی و نتیجه همراه هم تسویه می‌شوند؛ state دیررس دور نهایی را دوباره فعال نمی‌کند. تعارض STATE_CONFLICT اجرای قدیمی را متوقف می‌کند. خطای ذخیره snapshot را حذف نمی‌کند. ارسال هنگام بستن ناگهانی صفحه تضمین‌شده نیست؛ ذخیره پس از حرکت معتبر و checkpoint هنگام توقف لازم است.

با تغییر ناسازگار state، stateSchemaVersion افزایش می‌یابد. مهاجرت فقط با تبدیل صریح و آزموده؛ در نبود آن نسخهٔ قبلی مجاز حفظ یا دور تازه با توضیح روشن آغاز می‌شود. ذخیرهٔ قدیمی بی‌صدا حذف نمی‌شود؛ نسخهٔ دارای ایراد امنیتی برای ادامه تحویل داده نمی‌شود.

## ۶. تجربه و پذیرش

کنترل لمسی حداقل۴۴ پیکسل، فوکوس آشکار، نام خوانا برای دکمه، پشتیبانی صفحه‌کلید، عرض‌های۳۶۰/۳۹۰/۷۶۸/۱۲۸۰، صدا با اقدام کاربر و کاهش حرکت لازم‌اند. پیام موفقیت ذخیره باید به وضعیت واقعی اشاره کند. خروج، پاک‌سازی و شروع دوباره متمایزند؛ شروع مخرب تأیید روشن می‌خواهد.

اعتبارسنجی فایل و نتیجهٔ client ضدتقلب نیست؛ مبنای جایزهٔ مالی، رتبه‌بندی معتبر یا گواهی رسمی محسوب نمی‌شود. محتوای ویترین از پنل می‌آید؛ نمونهٔ آزمایشی خودکار عمومی نمی‌شود.

سه سطح: A اجرای مستقل؛ B شناسنامه و بررسی ساختار؛ C اجرا/ذخیره/ادامه/نتیجهٔ آزموده در میزبان. هیچ موفقیت ایستا به‌تنهایی ادعای C نمی‌دهد.

تحویل باید نام/نسخه/منبع و خروجی، آزمون‌های اجراشده و انجام‌نشده، محدودیت و شواهد را مشخص کند. آزمون‌های لازم: اجرای CSP، خروج و reload وسط فعالیت، ورودی ناتمام، توقف ساعت، پایان/خودارزیابی، قطع اتصال/receipt دیررس/تکراری، دو تب/پروفایل، نسخهٔ ناسازگار، پیام منبع نادرست و payload بزرگ، موبایل/صفحه‌کلید/صدا/کاهش حرکت.

برای تغییر کد سایت، PHP، Pint، build و CI طبق قواعد مخزن الزامی‌اند. انتشار عمومی پس از پذیرش مالک است. منابع قدیمی و فایل‌های نسخه‌های واردشده خودکار جایگزین نمی‌شوند.

## ۷. سابقه

تصمیم محتوایی مالک، ۲۰۲۶-۱۰-۰۷: در بازی `caravan-of-light` نسخهٔ ۳، پاسخ آموزشی با یک کنش مستقیم اجرا می‌شود؛ تأیید پاسخ/بسته‌بندی و ادامهٔ دستی حذف می‌شوند. خطا امتیاز کم می‌کند؛ پاسخ درست فانوس خاموش را روشن می‌کند و بازی خودکار جلو می‌رود. جزئیات در `caravan-of-light/14-direct-gameplay-revision.md` است. این تغییر با schema=2 و ruleset تازه و انتقال آزمودهٔ ذخیرهٔ مستقل انجام می‌شود؛ قرارداد پیام و SDK تغییر نمی‌کنند. تأیید شروع مخرب سفر طبق بخش ۶ حفظ می‌شود.

تصمیم محتوایی تازهٔ مالک، درخواست ۲۰۲۶-۱۰-۰۷ و تحویل محلی ۲۰۲۶-۱۰-۰۸: در `caravan-of-light` نسخهٔ ۵ (تکمیل کاندید ۴)، برد فرصت خواندن امتیاز دارد؛ فانوسک درخواست مأموریت و سرنخ را ارائه می‌دهد و CTA اختیاری کانال از برند مشترک در توقف/کارنامه افزوده شده است. جزئیات `caravan-of-light/16-ux-companion-and-channel.md` است. زمان خواندن به کاهش حرکت وابسته نیست. schema=2 و قواعد نسخهٔ ۳ حفظ، حالت اختیاری پنجرهٔ channel به خواننده افزوده، ذخیرهٔ مستقل v3/v4 با پشتیبان اعتبارسنجی می‌شود. SDK، sandbox و قرارداد پیام عوض نمی‌شوند؛ دعوت کانال شرط بازی یا نتیجه نیست.

تصمیم طراحی مالک، ۲۰۲۶-۱۰-۰۹: نسخهٔ ۲ بازی `bridge-builder` برای کاربران موبایل میز طراحی افقی تمام‌اندازه با ابزارها و دکمه‌های توضیح روی صحنه دارد. تمام‌صفحه/قفل جهت فقط در صورت پشتیبانی و مجوز مرورگر درخواست می‌شود؛ نمایش افقی خود رابط جایگزین آزموده است. sandbox و SDK تغییر نمی‌کنند. قواعد/schema=1 ثابت‌اند و ذخیرهٔ مستقل نسخهٔ ۱ با اعتبارسنجی و نگه‌داری عین بستهٔ قبلی ادامه دارد. جزئیات و محدودیت‌های آزمون در `_src/games/bridge-builder/README.md` ثبت شده‌اند.
